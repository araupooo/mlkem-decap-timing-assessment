Headline results

  • No timing difference between valid and implicitly-rejected decapsulations in any implementation. Largest adversarial median difference: +0.400% (Kyber reference, SYNTH-RAND, neither test significant). Per implementation: pyca 0.124%, liboqs 0.110%, Go 0.220%, kyber-ref 0.400%. No pair met the rerun rule (|median diff| > 0.5% AND p < 0.01), so no confirmation reruns were performed.
  • The noise floor is the finding for Go. Go's own VALID-vs-VALID null control differs by +1.496 µs (+1.155%, Mann-Whitney p = 0.0019) — larger than every Go adversarial effect. Sub-1% effects are undetectable for Go in this environment.
  • One discordant test pair (liboqs WRONGKEY): Welch's t-test flags it (p = 0.0006) while the median difference is +0.017% and Mann-Whitney does not flag it (p = 0.2418) — a mean/outlier effect from a few slow batches, not a distributional shift.
  • FIPS 203 does not mandate constant-time execution (the words "constant time" and "timing" do not appear in the standard); it requires the rejection flag to be destroyed, not returned (§3.3, §6.3). A null wall-clock result is therefore not a constant-time certification — and nothing here demonstrates exploitability either.
  • Absolute speeds (VALID median): liboqs 22.953 µs, pyca 52.187 µs, Go 129.482 µs, Kyber reference 133.157 µs.

Method

5 fresh keypairs per implementation; per keypair, 6 input classes × 20 batches × 1000 decapsulations; batch order shuffled per round; 200 warm-up decaps per keypair (discarded). Timed region: pure decapsulation. Input classes: VALID (valid encapsulation), FLIP1 (ct[0] bit flipped), FLIPMID (ct[543] bit flipped), WRONGKEY (valid ciphertext, different keypair), SYNTH-ZERO (all-zero ciphertext), SYNTH-RAND (random ciphertext). All times are microseconds per decapsulation (batch means, n=100 per implementation per class). Pairwise tests: Welch's t-test and Mann-Whitney U (large-sample normal approximations), 95% CI for the mean difference, Cohen's d. Null control: VALID batches split in half, tested VALID-vs-VALID. Rerun rule: |median difference| > 0.5% of the VALID median AND p < 0.01 — no pair met it.

Findings

  • F-1 — Informational (method): the Go null control drifts more than any adversarial effect — the noise floor, not a leak. Go VALID-vs-VALID: +1.496 µs (+1.155%), MWU p = 0.0019; largest Go adversarial difference is SYNTH-ZERO at +0.220%.
  • F-2 — Informational: liboqs WRONGKEY is discordant — Welch p = 0.0006 but median difference +0.017% and MWU p = 0.2418; a mean/outlier effect, which is why the protocol requires median + rank agreement.
  • F-3 — Positive: no timing difference between valid and implicitly-rejected decapsulations in any implementation (20 pairs, largest median difference +0.400%, none suspicious).
  • F-4 — Informational: absolute speeds differ widely; liboqs (AVX2) is fastest at 22.953 µs VALID median, ~5.6× faster than Go.
  • F-5 — Caveat: a null wall-clock result is not proof of constant-time execution, and not proof of exploitability either. FIPS 203 does not mandate constant-time execution; the Kyber/ML-KEM reference lineage has had real timing leaks despite constant-time-looking source (Clangover, CVE-2024-37880; KyberSlash).
  • F-6 — Informational: constant-time structure verified in source for the Kyber reference (verify() + cmov() in kem.c); the liboqs AVX2 path actually measured was not source-verified here; pyca/OpenSSL constant-time status was not verified from a primary source in this run.
